## 🔴 높음 (Critical) — 4건

### R-01 · Jedi 파서의 Python 동적 특성 대응 한계
**범주**: 기술 / Phase 1, 4
**내용**: Python의 duck typing, 메타클래스, 런타임 import 등으로 Jedi가 참조 해결에 실패하는 비율이 높을 수 있음. 대형 프로젝트에서 unsolved 비율이 과도하면 UX 품질 저하.

**영향**:
- 그래프가 unsolved 노드로 도배되어 가치 없는 시각화가 될 위험
- 사용자가 "쓸모없다"고 판단할 수 있음

**완화**:
1. **설계 원칙**: unsolved를 1급 시민으로 인정 (첨부 이미지에서 이미 요구) — 숨기지 않고 정직하게 표시
2. Phase 4 F19: Type Hint 기반 unsolved → solved 승격
3. Phase 4 F20: Duck typing 후보 opacity 50% 표시
4. Phase 4: mypy/pyright 외부 통합으로 정확도 보완
5. 리스크 게이트 Week 28: 타입 힌트 통합 후 unsolved 50% 감소 확인

---

### R-02 · SourcetrailDB 100% 호환성 유지 실패
**범주**: 아키텍처 / 전 기간
**내용**: Python 특화 기능(Django ORM, FastAPI route, dynamic import) 등을 추가하면서 원본 스키마를 변경하거나 enum 값을 오염시킬 위험.

**영향**:
- 원본 Sourcetrail GUI에서 DB 열람 불가 → 핵심 약속 파기
- 기존 Sourcetrail 사용자 이전 경로 차단

**완화**:
1. **확장 테이블 방식** 채택 (`edge_extension`, `node_extension`) — 원본 스키마 미훼손
2. 원본 C++ 소스에서 enum 직접 확인 후 1:1 매핑
3. **CI에 호환성 검증 자동화** (`scripts/compatibility_check.py`)
4. 릴리스 전 필수 — 원본 Sourcetrail Windows 빌드에서 샘플 DB 로드 성공 확인
5. PR 리뷰 체크리스트에 "스키마 호환성" 항목 고정

---

### R-03 · 1인 풀타임 번아웃 / 일정 지연
**범주**: 인력 / 전 기간
**내용**: 8개월 풀타임 단독 개발. 번아웃, 건강 문제, 동기 저하로 일정 지연 가능.

**영향**:
- 전체 일정 밀림
- 품질 저하 (테스트 축소 유혹)
- 최악의 경우 프로젝트 중단

**완화**:
1. **주 40시간 상한 엄수** — 주말 작업 금지
2. 매 Phase 종료 시 1-2일 버퍼 확보
3. MVP(Week 16)까지는 범위 축소 절대 금지, 이후는 유연
4. Phase 3 Week 22부터 기능 이월 결정 가능
5. 주간 자기 회고 (금요일 30분) — 무리 징후 조기 감지
6. **Beta(Week 16) 공개 후 피드백으로 동기 부여**

### R-04 · 성능 — 대형 프로젝트에서 UI 버벅임
**범주**: 기술 / Phase 1, 5
**내용**: 10만+ LoC 프로젝트에서 그래프 렌더링 또는 인덱싱 지연으로 실사용 불가능해질 위험.

**영향**:
- 타겟 사용자(대형 코드베이스 탐색자)에게 부적합한 도구로 전락
- 경쟁 도구(Understand 등)와의 차별화 실패

**완화**:
1. Phase 1부터 성능 벤치마크 정기 실행 (`scripts/bench.py`)
2. **리스크 게이트 Week 8**: 10만 LoC 그래프 60fps 체크
3. 뷰포트 컬링 + LoD (Level of Detail) 설계
4. Shallow 모드 기본값, Deep은 on-demand
5. SQLite WAL 모드, 인덱스 최적화
6. 실패 시: Phase 5 성능 전용 스프린트 확보

## 🟡 중간 (Medium) — 9건

### R-05 · QScintilla 커스텀 렌더링 한계
**범주**: UI / Phase 2
**내용**: F4 Syntax Decoration의 연산자 치환, 중첩 괄호 크기 차등, 닫는 블록 annotation은 QsciStyle만으로 구현 어려움.

**완화**:
- QPainter 오버라이드로 decoration 그리기
- 실패 시 일부 decoration 기능 축소 (연산자 치환은 옵션 기본 off)

### R-06 · QScintilla Python 바인딩 빌드 이슈
**범주**: 의존성 / Phase 0
**내용**: `PyQt6-QScintilla` 휠이 Python 3.12 / Windows x64에서 없을 가능성.

**완화**:
- Phase 0 D2에 PyPI 휠 확인
- 휠 없으면 SIP 컴파일 직접 (Visual Studio Build Tools)
- 대안: Python 3.11로 다운그레이드 검토

### R-07 · Rope Rename 회귀 / 불안정성
**범주**: 기술 / Phase 3
**내용**: Rope 기반 Smart Rename(F5)이 edge case (데코레이터, 메타클래스, 동적 속성)에서 실패할 수 있음.

**완화**:
- 미리보기 필수 (사용자 확인 후 적용)
- Undo 지원
- **리스크 게이트 Week 22**: 회귀율 > 1% 시 LibCST 기반 재작성 검토

### R-08 · 레이아웃 알고리즘 품질 (그래프)
**범주**: UX / Phase 1
**내용**: Sugiyama 계층형 레이아웃만으로는 복잡한 그래프에서 엣지 교차가 많이 발생.

**완화**:
- Phase 1 1차는 단순 Sugiyama
- Phase 5에 개선 여지 (force-directed 보정 강화, 또는 ELK 알고리즘 포팅)

### R-09 · 패널 간 이벤트 피드백 루프
**범주**: 아키텍처 / Phase 2
**내용**: 이벤트 버스 기반 동기화가 무한 루프를 일으킬 수 있음 (A → B → A).

**완화**:
- 시그널에 소스 태그 포함 (자기 자신 시그널 무시)
- 디바운싱 (200ms) 적용
- 통합 테스트로 루프 탐지

### R-10 · 프레임워크 플러그인 엣지 케이스
**범주**: 기능 / Phase 4
**내용**: Django/Flask/FastAPI/SQLAlchemy 각각 무수한 사용 패턴. 전부 커버 불가능.

**완화**:
- 첫 릴리스는 **대표 패턴**만 커버 (공식 문서 예제)
- 누락 패턴은 GitHub Issues로 수집 → v1.1+로 개선
- 각 플러그인마다 샘플 프로젝트 golden test

### R-11 · mypy/pyright 외부 프로세스 느림
**범주**: 성능 / Phase 4
**내용**: F19의 외부 타입 체커 통합이 대형 프로젝트에서 수 분 걸림.

**완화**:
- 선택적 기능, 기본 **off**
- 활성화 시 백그라운드 실행, 증분 모드 사용
- 결과 캐싱

### R-12 · PyInstaller 바이너리 크기 과다
**범주**: 배포 / Phase 5
**내용**: PyQt6 + QScintilla + Jedi + Rope + Tree-sitter 번들 시 200MB+ 가능.

**완화**:
- UPX 압축
- 불필요 모듈 제외 (`--exclude`)
- One-folder 모드로 시작, 실패 시 One-file 재검토
- 목표: < 200MB 인스톨러

### R-13 · Windows Defender / SmartScreen 오탐
**범주**: 배포 / Phase 5
**내용**: 서명 없는 PyInstaller 바이너리가 악성 프로그램으로 오탐될 수 있음.

**완화**:
- Inno Setup 사용 (더 낮은 오탐률)
- 가능하면 코드 서명 인증서 구매 (선택)
- 오탐 발생 시 Microsoft에 제외 요청 제출

## 전사적 완화 원칙

1. **조기 실패 (Fail Fast)**: PoC 단계에서 기술 불확실성 해소
2. **이중 방어선**: 호환성 검증은 개발자 로컬 + CI 양쪽 모두
3. **범위 보호**: MVP(Week 16)까지는 범위 축소 금지, 이후는 유연
4. **건강 우선**: 번아웃은 프로젝트 리스크 #1 — 근로 시간 상한 엄수
5. **투명한 문서화**: 매 Phase 회고에 "어려웠던 점" 기록 → 다음 프로젝트에 반영
6. **백업 전략**: 주간 오프사이트 백업 (GitHub + 로컬 외부 드라이브)
